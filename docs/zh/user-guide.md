## 能力位模型

mibee-eye 是一台带可选端侧智能的本地采集设备。每项智能功能都**故障开放
（fail-open）**：模型文件缺失、构建未编入对应 feature、或主机跑不动时，
设备只是不通告该能力位——产品其余部分不受影响，界面对应控件自动隐藏，
绝不会出现假数据。

设备通过 `GET /api/capabilities` 发布实时能力集；Web 界面加载时读取它，
只渲染本机真正具备的功能：

| 能力位 | 含义 |
|--------|------|
| `ai` | 视觉目标检测（NanoDet）——检测叠加框、`/api/detections`、`ai_detection` 事件 |
| `zones` | 用户绘制入侵/越线区域 + 基于跟踪的 `zone_event`（依赖 `ai`） |
| `audio_ai` | 声音事件检测（YAMNet）——`source: "audio"` 的 `alarm` 事件 |
| `audio_records` | 持久听觉记录——**记录**视图与 `GET /api/audio/records` |
| `voice` | 唤醒词 + 离线语音转写——`voice_transcript` 事件 |
| `chat` | 本地 LLM 对话——对话面板与 `POST /api/chat` |
| `vlm` | 告警画面图像描述——`alarm_description` 事件 |
| `ocr` | 端侧文字识别——`POST /api/ocr` |
| `substream` | 至少一路运行中的相机开启了低分辨率子码流 |

看不到某个能力位 = 该功能未开启，而不是坏了。[启用 AI 能力](#启用-ai-能力)
一节说明如何逐项打开。

## 首次登录

1. 浏览器打开 `https://<设备地址>:8443`。首次启动使用自签 TLS 证书，浏览器
   会告警——点"高级 → 继续前往"即可，或安装自己的证书（见
   [配置参考](configuration.md#tls-证书管理)）。
2. 首次访问设备会进入初始化流程：设置管理员用户名与密码。该账号保存在设备上。
3. 之后在登录页使用该账号登录。用户名留空等价于 `admin`（单用户便捷约定）。

## Web 界面

顶栏共五个视图——**实时**、**相机**、**设置**、**状态**、**设备**——右侧是
语言（中/英）与主题（日/夜）切换。所有视图均按能力位渲染。

### 实时视图

实时视图显示所选相机的视频流，叠加层直接画在画面上：

- **检测叠加**（能力位 `ai`）：绿色目标框带类别与置信度，随每次检测刷新。
- **区域叠加**（能力位 `zones`）：已保存的区域绘制在画面上；区域触发时高亮。
- **流工具栏**：开始/停止、快照、画质（主码流/子码流——子码流为省带宽的
  低分辨率流）、旋转，以及**区域编辑器**按钮。多相机时每个画面块自带控件。

### 区域编辑器

区域是用户手绘的 AI 监视范围，分两类：

- **入侵检测**（`intrusion`）——多边形（≥ 3 个点）。被跟踪目标进入区域并
  滞留达到设定时长即告警。
- **越线检测**（`line_cross`）——线段（恰好 2 个点）。被跟踪目标越过即
  告警，事件会注明穿越方向。

画一个区域：

1. 在实时视图的流工具栏点击**区域**按钮。
2. 当前视频帧被冻结为底图。在底图上点击取点：多边形（入侵）或两个点
   （越线）。*撤销*删除上一个点，*清空*删除全部。
3. 给区域命名、选择类型、设置滞留秒数（仅入侵类需要）。
4. **保存**写入该相机的区域列表——立即生效，无需重启。

区域依赖 `ai` 能力位（跟踪建立在检测器之上）；越线/入侵事件经 `zone_event`
SSE 事件与告警 toast 送出。

### 对话面板

设备通告 `chat` 能力位时，右下角悬浮一个圆形**对话按钮**。打开后输入消息，
端侧 LLM 在面板内作答。面板保留最近的对话轮次，可以追问。语音交互的回复
也会出现在同一面板（面板关闭时以 toast 提示）——见
[和设备说话](#和设备说话语音交互)。

LLM **在设备本地运行**（llama.cpp + Qwen3），不向任何云服务发送数据。

### 相机 / 设备 / 状态 / 设置

- **相机**——添加、编辑、启停、删除采集设备；每相机配置（分辨率、FPS、
  子码流、旋转、水印…）都在这里。增删改即时生效，无需重启服务。
- **设备**——枚举本机 V4L2 视频与 ALSA 音频设备，并列出视频设备支持的
  采集格式。添加相机/麦克风前先用它确认设备号。
- **状态**——设备标识（名称、型号、固件、运行时长）与协议运行态
  （ONVIF / GB28181 是否在运行）。
- **设置**——统一配置编辑器：协议节（ONVIF、GB28181、RTMP 推流、录像、
  水印）保存即热生效；界面偏好（语言、主题）按浏览器持久化。

## 告警与通知

所有告警走同一条 SSE 通道（`/api/events`）并以 toast 形式呈现在界面。
视觉告警携带目标类别与置信度；声音告警携带声音类别（如 `Dog`、`Glass`、
`Smoke detector`）；区域告警注明区域名与穿越方向。

启用 `vlm` 能力位后，每条视觉告警还会触发一句**触发画面描述**（"发生了
什么"），由端侧视觉-语言模型生成。告警本身**绝不因描述而延迟**——描述在
数秒后作为独立通知到达，并标明所属告警。

GB28181 启用且平台已订阅时，同一条被接受的告警还会以 GB Alarm NOTIFY
转发（Method 5 / Type 2 / Priority 4）。

### 听觉记录

听觉面识别到的一切都会写入**持久文本记录**（能力位 `audio_records`）：
每条触发的声音事件（类别名与得分）、每次语音交互（唤醒词与完整转写）。
打开 Web 界面的**记录**视图浏览——最新在前、可按类型筛选、一键清空。
程序可经 `GET /api/audio/records` 读取同一份日志（`DELETE` 清空）。日志
保留最近 1000 条；记录跨重启保存。

声音事件检测与语音监听**只在配置中显式开启后才运行**——麦克风是隐私敏感
输入，所有监听类功能一律默认关闭、主动开启。

## 和设备说话（语音交互）

启用 `voice` 能力位后，设备在麦克风上保持一个唤醒词监听器（等待期间不
录制、不传输任何音频——关键词模型只在本地比对极短的音频指纹）：

1. 说唤醒词——默认为**小蜜蜂**。
2. 设备采集随后几秒音频（默认 4 秒）。
3. 采集的音频**离线**转写（paraformer 中文模型）。
4. 转写文本以 `voice_transcript` 通知送出。若 `chat` 能力位也已开启，
   文本交由本地 LLM 作答；配置了 TTS 时回复还会通过扬声器播报。

使用提示：

- 唤醒词之后**再**说话；采集窗口从识别到唤醒词才开始。一句话尽量在采集
  窗口（4 秒）内说完。
- 唤醒词始终不响，先查麦克风输入设备与电平（见[故障排查](#故障排查)）。
- 唤醒灵敏度与关键词表都是配置键（`keywords_threshold`、`keywords_file`）。

## 启用 AI 能力

所有 AI 引擎**默认关闭**。它们在 `config.local.toml`（二进制同目录，或
`--config` 指定的路径）中配置，改后需重启服务；随后自动出现在
`/api/capabilities` 里。

```toml
[audio_ai]        # 声音事件（YAMNet）—— source: "audio" 告警
enabled = true
classes = ["Dog", "Bark", "Baby cry, infant cry", "Glass", "Siren"]

[voice]           # 唤醒词 + 离线转写（需 voice feature 构建）
enabled = true

[llm]             # 本地 LLM 对话（需 llm feature 构建）
enabled = true

[tts]             # 语音播报（sherpa-onnx CLI + vits-melo）
enabled = true

[vlm]             # 告警画面描述（需 llm feature 构建）
enabled = true

[ocr]             # 文字识别（POST /api/ocr）
enabled = true
```

构建要求：`voice` 需要 `voice` cargo feature（构建期链接 sherpa-onnx 静态
库）；`llm`/`vlm` 需要 `llm` feature 且 CPU 支持 **AVX2**（约 2013 年后的
x86-64 均可；Sandy Bridge 及更老的主机只能用 voice-only 构建）。模型文件
缺失时对应引擎一律降级为"关闭"——见[模型资产](#模型资产)。

子码流与区域不需要 TOML：子码流是 Web 界面里按相机设置的配置键
（`config.substream`），区域直接在界面上画。

## 模型资产

模型文件**不进 git**，部署时下载到 `models/` 目录。
[`models/README.md`](../../models/README.md) 是权威表格（来源、体积、
许可）。概要：

| 路径 | 模型 | 体积 |
|------|------|------|
| `models/nanodet-m.onnx` | 视觉目标检测（既有） | ~10 MB |
| `models/audio/yamnet.onnx` + `silero_vad.onnx` | 声音事件 + 语音存在 | ~18 MB |
| `models/voice/kws/`、`models/voice/paraformer/` | 唤醒词 + 转写（sherpa-onnx） | ~250 MB |
| `models/voice/melo/` | TTS 音色（vits-melo zh_en） | ~165 MB |
| `models/llm/qwen3-0.6b-q8_0.gguf` | 对话 LLM | ~640 MB |
| `models/vlm/qwen3-vl-2b-instruct-q4_k_m.gguf` + `mmproj-…gguf` | 告警描述 | ~1.5 GB |
| `models/ocr/*.onnx` | PP-OCR 检测 + 识别 | ~21 MB |

文件缺失不会影响服务运行——对应引擎只是保持关闭。

## 离线自检

每个引擎都有确定性 CLI 自检：对本地文件完整跑一遍管线并输出 JSON——
部署后先自检再怀疑服务：

```bash
mibee-eye --selftest-audio clip.wav      # 声音事件：分类一段 WAV
mibee-eye --selftest-voice sample.wav    # 语音：唤醒词 + 转写
mibee-eye --selftest-llm "你好"          # 对话：一次 LLM 补全
mibee-eye --selftest-tts "你好，世界"     # TTS：合成并播放
mibee-eye --selftest-vlm frame.jpg       # VLM：描述一张 JPEG
mibee-eye --selftest-ocr page.jpg        # OCR：识别文字
```

自检只有在模型加载成功且输出合理时才通过；文件或 feature 缺失时以引擎
自身的报错失败。

## 故障排查

| 症状 | 可能原因 / 处理 |
|------|----------------|
| 某功能的控件始终不出现在界面 | 对应能力位未开启。先看 `GET /api/capabilities`，再核对配置 `enabled`、二进制编入的 cargo feature、模型文件三者。 |
| 唤醒词始终识别不到 | 查输入设备（`arecord -l`、**设备**视图）与采集电平。用一段录有唤醒词的音频跑 `--selftest-voice sample.wav`。外接 USB 麦克风远比笔记本内置麦克风灵敏。 |
| TTS 无声 | 跑 `--selftest-tts "test"`——覆盖 sherpa-onnx 二进制、音色资产与 `aplay`。确认存在输出设备且音量未静音。 |
| 视觉告警触发但没有描述 | `vlm` 能力位未开启（模型缺失、配置关闭或 CPU 不支持 AVX2）。描述还有节流：同时只跑一个，连续告警按间隔下限合并而非堆叠。 |
| 区域事件从不触发 | 区域依赖 `ai`（跟踪）。确认检测框本来就有、相机在运行、区域确实覆盖目标会经过的位置。 |
| LLM 回复很慢 | 小主机跑 GGUF 推理就是慢；默认 Qwen3-0.6B Q8_0 在现代笔记本上短回复需数秒。可调低 `max_tokens`、换 Q4_K_M 量化，或把 LLM 挪到更快的主机。 |
| 声音告警频繁误报 | 调高 `audio_ai.threshold`、缩短 `classes` 列表，或加大 `cooldown_secs`。 |
| 记录视图没有内容 | 该能力位需要音频引擎活跃（`audio_ai` 或 `voice`）。而且记录只在引擎运行期间累积——引擎没在跑的时段不会留下任何痕迹。 |
| 机器负载高时 `POST /api/chat` 超时 | 多个重型引擎会争抢 CPU。推理线程数已自动设上限（`OMP_NUM_THREADS` = 核数/2，最高 4）；关闭其他引擎或升级主机。 |

其余问题从日志入手（`RUST_LOG=info` 或服务 journal）——每个引擎启动时
都会明确记录自己为何未激活。
